# 3. MuJoCo physics in the sim host, plain three.js in the browser

Date: 2026-11-19 · Status: accepted · Replaces parts of [ADR 2](0002-react-three-fiber-simulator.md)

## Context

ADR 2 chose no physics engine and React Three Fiber in TypeScript. Since then the team wants to see
what happens to the robot's joints: servo loads, springs, tipping, wheels slipping. A simple motion
model cannot show any of that. The dog core already talks to the Pico over a JSON UART protocol, so
the simulator can sit behind that protocol without changing the core.

## Decision

- **MuJoCo** simulates the robot in the Python sim host (`apps/sim-host`). The robot is an MJCF file
  built from the drawing and the CAD parts.
- The sim host **emulates the Pico firmware** behind a virtual serial port, so the core runs unchanged.
- The browser viewer (`apps/dog-simulator`) only draws. It uses **plain three.js with JSDoc types**
  (`// @ts-check`) and Vite, not React Three Fiber and TypeScript. The view is one scene built from
  MuJoCo's geoms, and the panel is static HTML. React adds no value there, and JSDoc keeps every file
  readable without a compile step.
- Project documentation uses **MkDocs Material**, with the Python API generated by mkdocstrings.

Alternatives considered: MuJoCo in the browser through WebAssembly (headless tests would need a
browser, and the core still runs in Python); keeping the simple motion model (cannot show joint loads).

## Consequences

- The sim host depends on `mujoco` and `websockets`.
- The robot model must be kept in step with the mechanical design. Its placeholder values are listed
  in docs/simulator/robot-model.md.
- The simulator also documents the behaviour the real Pico firmware needs (docs/simulator/pico-emulator.md).
